# 从研究要求构建模型

<!-- README-I18N:START -->

[English](requirements_driven_model_building.md) | **中文**

<!-- README-I18N:END -->

**状态：工作流设计。** 用户提供数据和研究要求，agent 将数据契约与已有方法技能结合，提出并构建合适模型。现有项目代码提供复现案例，不把每个新任务固定为同一种模型。本文不注册训练工具，也不创建工作流引擎。

## 能力库、任务与参考案例

| 部分 | 职责 |
|---|---|
| `methods/` | 解释适用性、科学假设、验证和解释边界 |
| `skills/` | 说明数据准备、软件操作、模型构建和产物检查 |
| 数据说明 | 定义样本单位、字段、量纲、时空口径、特征可获得时间与允许用途；实际文件留在 Git 外 |
| `catalog/` | 声明真实工具能力与实现状态 |
| MCP 与核心程序 | 暴露已有声明和受控操作，未来编排复用这些服务 |
| 复现案例 | 固定参考实现、输入契约、执行方式及预期检查，供独立比较 |

两种任务模式共用能力库。**构建**按新研究要求选择方法，并记录选型理由；**复现**按指定且已冻结的参考案例执行，比较约定产物。新算法不必复现另一个算法的预测值，其科学评价另行确定。

## 用户提供什么

首次交互只需用户提供授权输入引用、目标或研究目的，以及自然语言建模要求。其余规格由 agent 结合已有元数据和技能整理，仅对实质影响任务的缺失决策提问。用户不必知道后端学习器编号、服务器名或命令。

## 完整使用步骤

| 步骤 | Agent 的工作 | 所需产物或停止条件 |
|---|---|---|
| 1. 理解要求 | 明确预测、比较、解释或其他指定目的，记录目标、使用场景与限制 | 范围明确的任务规格；建模前解决目标和时间语义的歧义 |
| 2. 匹配数据与技能 | 将输入结构、单位与方法及操作技能匹配，核对真实实现状态 | 数据契约及能力、缺口清单；缺少特征、依赖或未支持方法均明确保留 |
| 3. 设计验证 | 按预期应用确定划分单位和时间边界，预留最终评估集，约定基线、指标方向和资源预算 | 固定的数据划分与评价方案，不在留出数据上拟合变换 |
| 4. 构建模型 | 生成任务代码或适配合适实现，将路径、列、算法和预算显式化 | 可审查的源码与配置、合成契约检查；生成代码不自动受信任或注册 |
| 5. 执行限定任务 | 在授权输入、输出和计算边界内使用已审查操作 | 依赖、预检、进程回执和全新产物；阶段失败阻断依赖它的步骤 |
| 6. 评价与解释 | 冻结开发选择，按设计完成约定的最终评估，回答所需解释问题 | 指标、基线、失败与覆盖检查及解释边界；预测归因本身不构成因果识别 |
| 7. 比较并交付 | 仅在相关且获授权时运行参考案例，检查模型输入兼容与复现结果 | 模型说明、源码与配置版本、输入契约、划分记录、指标和产物索引；明细与模型留本地 |

重复实体、空间结构、时间趋势和滞后特征会影响划分设计。插补、标准化、编码和特征选择等拟合步骤放在相应训练或重抽样范围内。预测复用训练期变换、字段顺序、类型和水平，不通过反复查看最终测试集选出偏好模型。

## 参考代码如何验证能力

每个参考案例需要稳定案例编号与源码版本、授权输入说明、原有方法与配置、运行环境及依赖、输出契约、比较指标与容差、已知限制。私有代码根、数据和预期明细输出通过本地映射维护。文件存在或旧成功记录不等于当前复现通过。

分别实施三种检查：接口与失败行为的合成工程检查；按约定输入复现指定原计算；对新要求模型的科学评价。随机计算记录种子、划分身份及允许的数值或统计差异，不强求文件字节完全相同。参考实现本身也先审核，再决定是否用其产物作为验收目标。

## 接入边界

首个完成源码核对的示例为[空气质量臭氧回归案例](references/air_quality_o3_reference_ZH.md)。它提供具体的复现与适配依据，原有特征、划分与预算不限制所有新任务。

面向人类的工作流叙述放在这里，可复用软件操作放对应模型技能，见[现有模型分类](../../skills/model/machine_learning/README_ZH.md)。私人复现输入和模型产物使用数据工作区，非秘密来源映射放 CONFIG_DIR，认证独立管理。

当前模型参考条目不是训练适配器。MCP 可以发现已注册能力、读取技能入口，但不能执行任意新生成代码。经过验证的阶段连接在已实现并审查引擎和适配器后，才归入 `workflows/`；未实现操作保留为缺口，不虚构可调用工具编号。

## 建议实现顺序

1. 为参考案例补齐数据字典和稳定样本键，冻结源码、样本、划分与比较契约。
2. 将准备、拟合调参、评价和解释拆成可独立调用操作。保留旧源码，对齐或验证修正单独版本化；先用合成输入检查失败行为及分支对齐。
3. 实现任务规格加载、能力匹配、限定操作适配器及产物检查。仅把已实现并审查的适配器接入 catalog/MCP，阶段编排另行实现。
4. 在单独授权的计算任务中验证首个小范围复现，再扩展其他用户指定模型和案例；按各任务要求检查模型选择与评价，不强制所有任务使用原随机森林。

## 数据与项目结果

数据和项目结果按[资产规范](../../harness/assets_ZH.md)管理。Git 外共享 `assets/data/<stage>/<dataset-name>/<version>/`，数据目录使用实际名称；项目按配置引用固定版本，跨阶段不复制。新结果保存到 `assets/results/<project_id>/<run_id>/<stage>/<tool_id>/`，运行记录和临时文件留在该批次内。新调用同时提供项目和阶段。计算与检查 → 人工复核 → 将选定数据登记到新版本；不覆盖原始数据或既有版本。个人配置、认证及凭据继续独立管理。旧文件不迁移，自动审批和入库服务尚未实现。
