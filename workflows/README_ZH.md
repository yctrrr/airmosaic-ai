## 后续定义的条件

后续 `<pathway_id>/workflow.yaml` 需明确版本、用途、适用阶段、输入输出、真实工具编号、依赖、产物连接、检查条件、人工前置准备及停止规则。路径专属契约可放同目录。定义还需要经过审查的引擎和有效验证才能执行；新增 YAML 不会产生能力或授权。

规划中的引擎先检查完整路径，再委托现有服务执行单项工具，登记产物，并逐次检查交接。检查失败时保留部分产物并阻断下游；恢复时先核对已经发生的外部副作用。过程成功、契约检查与科学验收保持独立状态。

未来目录服务可直接索引此处定义，不重复维护另一份。本地 MCP 和命令行已共用单工具服务；工作流服务实现后再接入。目前没有研究阶段自动衔接。第二步继续仅列概念方法，不含具体数据、参数值或实现。

## 数据与项目结果

数据和项目结果按[资产规范](../harness/assets_ZH.md)管理。Git 外共享 `assets/data/<stage>/<dataset-name>/<version>/`，数据目录使用实际名称；项目按配置引用固定版本，跨阶段不复制。新结果保存到 `assets/results/<project_id>/<run_id>/<stage>/<tool_id>/`，运行记录和临时文件留在该批次内。新调用同时提供项目和阶段。计算与检查 → 人工复核 → 将选定数据登记到新版本；不覆盖原始数据或既有版本。个人配置、认证及凭据继续独立管理。旧文件不迁移，自动审批和入库服务尚未实现。
