# 四步交接与可追溯性

本文件定义人工交接的检查方法，没有自动执行器或强制运行时契约。不得把固定样本量、相关系数或单项测试当通用科学验收门槛。原始数据与私人日志留在授权本地，本轮不读取。

| 交接 | 需要说明 | 接收条件 |
|---|---|---|
| 01 → 02 | 活动、能源、技术的定义、单位、分类、覆盖与来源类别 | 核算边界和方法语义明确；02 当前仅讨论方法，不附具体数据或代码 |
| 02 → 03 | 空间/时间分配与物种映射方法、守恒及缺口检查 | 后续任务自行确定兼容的模型输入契约，不从目录存在推断已生成模型输入 |
| 03 → 04 | 浓度单位、网格、地表定义、时间平均、有效范围及验证摘要 | 浓度、人口及健康口径能配对；观测验证标准按任务制定 |
| 共享 → 各步 | 方法适用性、版本、边界和比较设计 | 不复制 skill，不引入排放具体实现，不将模型参考当可执行接口 |

## 记录和比较

区分方法选择、工程运行和科学验收。明确基准与干预情景、允许变化的条件和共同有效范围；来源追溯不能证明因果识别。缺失项和未运行事项单独列出。

已支持工具的 run-tool 记录在 LOCAL_WORKSPACE 的 runs/<run_id>/record.json，保留允许的脱敏元数据；它不是完整跨层来源链或科学验收服务。未适配流程不自动获得这些保障。详见[四步流程](../../harness/four-step-workflow.md)与[执行指南](../../harness/usage/run-tool.md)。
