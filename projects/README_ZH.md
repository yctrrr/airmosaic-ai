# 科学研究项目

[English](README.md) | **中文**

每个项目围绕一个具体科学问题组织实验，明确假设、研究范围、数据引用、比较设计、解释和人工复核。[工作流](../workflows/README_ZH.md)提供可复用的数据与技能组合，项目引用这些组合并说明需要哪些证据。[方法库](../methods/README_ZH.md)提供科学依据，[技能](../skills/README_ZH.md)提供计算机操作步骤。

## 编号与身份

- 目录采用 `0001_<topic>`、`0002_<topic>`，使用四位递增编号和有含义的小写主题名。从 `0001` 开始，新增项目取下一个未占用编号；已有编号不重排、不重复使用。
- 编号用于展示和导航，与四个研究阶段分开，不规定执行先后。
- 保留不含编号的稳定 `project_id`，符合执行器的小写标识规则。`project.json` 同时记录展示编号和稳定标识，用于关联项目目录、执行回执及兼容输出位置。
- 一个项目可引用多个工作流和研究阶段，一个工作流也可服务多个项目。共享输入按版本引用，项目不重复复制数据或流程代码。

## 最小组成

| 文件 | 职责 |
|---|---|
| `README.md` 与 `README_ZH.md` | 研究问题、范围、数据与工作流引用、当前状态 |
| `project.json` | 展示编号、稳定标识、固定输入版本、工作流和工具引用、计划实验 |
| `study-plan.md` 与 `study-plan_ZH.md` | 假设、比较设计、开发与测试分离、验收标准 |
| `review.md` 与 `review_ZH.md` | 待复核模板及人工决定的记录方式 |
| `experiments/<experiment_id>/`（可选） | 可共享的具体实验协议、prompt 和经审查的实验代码；不重复注册工具或宣称通用编排已实现 |
| `results/`（本地或私人目录） | 实际生成代码、配置、实验产物、评价及审核依据；不自动共享 |

## 使用与存储

1. 阅读科学问题和研究方案，明确允许的数据范围、实验设计和计算预算。
2. 核对引用的工作流和真实工具编号，参考配置示例，在 `${AIRMOSAIC_CONFIG_DIR}/projects/<project_id>/` 准备本次非秘密任务参数。
3. 对已注册工具先预检，再使用稳定项目标识执行已授权实验。在私人结果中记录实验标签、配置哈希和运行编号。
4. 按预定科学标准比较产物，将人工复核、批准用途与进程完成分别记录。

实验与结果归属 `projects/<number_topic>/`，其中 `results/` 保存生成代码、配置、指标、预测、图表与审核依据，内部布局按研究任务选择。这是归属约定，不是固定输出文件模板。私人结果使用仓库外的项目目录，个人路径映射留在 Git 外；仓库中的项目 `results/` 已被 Git 忽略，但忽略规则不自动赋予执行器写入权限。

人类科学审核决定修订实验、仅在项目中保留结果、发布报告，或将选定成果纳入 `assets/`。项目保留实验原件与审核记录。程序运行成功或生成文件不表示已经批准。资产内部组织方式留待后续确定，见[结果与审核约定](../harness/assets_ZH.md)。

当前适配器仍使用原有外部结果位置，尚不支持直接写入新的项目目录；不能用 Git 忽略规则绕过路径检查。已有具体项目示例描述的是实际兼容位置，历史结果继续保留，后续另行实现并授权迁移。公开项目文件可包含经审查的研究设计、协议、代码与引用；个人设置、私人研究细节、专用路径、凭据和逐条结果留在 Git 外。

`project.json` 当前供人类和代理阅读，不是命令行参数文件，也不会自动加载。项目发现、多实验编排、审批和入库服务尚未实现；项目文件不注册工具，也不授予执行权限。

子目录与文件名按研究任务确定，不统一强制运行编号、阶段及工具层级；保留配置、来源和产物清单。项目目录写入支持实现前，当前适配器继续遵守各自已有的输出契约。
