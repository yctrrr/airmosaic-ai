# 两套维护配置的常见故障

[English](build-troubleshooting.md) | **中文**

保留原失败案例，定位第一个有效错误。修正应进入新编译/运行目录，记录源码、设置与结果。

| 现象 | 检查与处理 |
|---|---|
| 缺子模块或原生表 | 核对所选模型版本及 Classic 递归子模块；v35l 静态表需与该模型版本一致，不能借另一机理文件。 |
| 缺编译器、NetCDF 或运行库 | 使用匹配 C/Fortran 库及同一编译/运行环境，核对 `nf-config`、`nc-config`、程序链接与 CMake 日志；无关 conda 运行库可能干扰。 |
| 旧 make 模块顺序错误 | 使用提供的依赖文件和串行 `-j1`，不要混入另一配置的旧对象文件。 |
| 不识别旧 `-openmp` | 实测 Intel 环境明确使用 `-qopenmp`，保留文档完整参数。 |
| 原生配置解析失败 | 保留固定标签列及全部菜单行，使用模板；每次调用前 `ITER` 都需要两行。 |
| 气象读取失败或时钟错误 | 核对真实 I3 两端和平均区间，本分量采用示范的完整三小时；CN/ApBp 放在原生常量目录。 |
| 无法打开 UV/TOMS | 使用旧 BPCH 布局及核验转换，不能只改 NetCDF 文件名；保留 UV 原值和 TOMS 重映射/元数据。 |
| 段错误或栈问题 | 主线程执行 `ulimit -s unlimited`，工作线程用 `OMP_STACKSIZE=256M`；核对资源和原错误，增栈不能修复未初始化物理数组。 |
| 启用被排除过程 | 分量配置有意拒绝排放、输送、混合和沉降；恢复文档分量，或另行设计完整过程运行。 |
| 退出零却无结果 | Fortran STOP 可能返回零；同时要求原生完成、本次目标、新写结束重启和独立内容核验。 |
| 已准备输入哈希不符 | 不绕过记录；修改原生设置后，重新准备并复核配置。 |
| 已有输出、部分传输或额度阻断 | 保留文件，检查作业/进程/记录并复用健康工作；不重置台账、不清未知锁、不盲目重复积分或拟合。 |
| 梯度不一致 | 核对示踪物编号、基线/正/负顺序、单位与格点；检查全部预定步长及局地误差，不改阈值或隐去最小步长失败。 |
| aerosol-feedback-adjoint 提示 | 仍属未解决的导数覆盖边界，全域条件通过不能修复缺失导数。 |

从 [Classic](usage_ZH.md) 或 [v35l](adjoint_ZH.md) 教程开始。失败旧版在活跃 skill 外可恢复保存，不作为额外维护路线。另见 [14.8.0 调试说明](https://geos-chem.readthedocs.io/en/14.8.0/geos-chem-shared-docs/supplemental-guides/debug-guide.html)。
