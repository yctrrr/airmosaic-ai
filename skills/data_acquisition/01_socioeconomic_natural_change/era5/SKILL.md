**Status: reference.** Includes website instructions, Python API examples and request JSON; no run-tool adapter.

For first use, follow the [onboarding guide](../../../../harness/usage/era5-first-api.md) for registration/login, dataset terms, API credentials, environment preparation, requests and validation, recording actual times.

## Workflow

Read the [data provenance, uncertainty and normalization method](../../../../methods/01_socioeconomic_natural_change/era5.md) before choosing variables and processing: reanalysis identity, units, instantaneous/accumulated periods, spatial representativeness and missing times. Do not apply station-observation hourly-validity thresholds to ERA5.

1. Define the question, dates, UTC times, region, variables and vertical levels. Distinguish single levels, pressure levels, ERA5-Land and daily statistics; changing a filename does not adapt a request.
2. Read the [method](../../../../methods/01_socioeconomic_natural_change/era5.md) and choose the CDS website or Python API using the [download guide](../../../../harness/usage/copernicus-downloads.md).
3. The user completes CDS login, dataset terms and credential preparation; the official client uses credentials internally.
4. Check parameters against a request generated by the current form. Start small, then plan batches by date, variable and level.
5. Verify format, variables, time, grid, units and completeness before handing off files and metadata.

## Two acquisition routes

| Route | Sequence | Authentication and validation boundary |
|---|---|---|
| Website | User logs into CDS → opens the single-level product Download page → checks variables, dates, UTC times, region and format → checks terms without reaccepting already accepted terms → submits → waits → saves to the task output → validates | Existing user session; no local API token required. Do not export account details, cookies or signed links |
| Python API | Check product and terms → prepare non-secret request JSON → explicitly select a credential mode in a dedicated task process → submit one small request using the official client → verify task, file and content | User-hidden token input or explicitly authorized internal reuse of an existing `.cdsapirc`; the agent does not open the file or read the token |

See the [first-use guide](../../../../harness/usage/era5-first-api.md) for page steps and the [download guide](../../../../harness/usage/copernicus-downloads.md) for Python code and credential modes. Check the original task state after failure or interruption before deciding what to do next.

## Verified example

Verified on 2026-10-26: single-level `2m_temperature`, 2024-01-01 00:00 UTC, north/west/south/east `[40, 110, 35, 115]`, GRIB. See the [example](references/api-download-example.md) for download and content results.

Use its request with `selection = "era5-single-levels"` and `credential_mode = "existing_file"` in the full Python example after directory checks. The example covers installation, file preparation, invocation, GRIB decoding and validation.

## Boundaries

- Requests: `AIRMOSAIC_CONFIG_DIR/copernicus/`; downloads: `AIRMOSAIC_LOCAL_WORKSPACE/output/<run_id>/era5/`; validated cache: `data_cache/era5/`. Dedicated browser sessions may use `AIRMOSAIC_AUTH_DIR/browser_profiles/copernicus-cds/`. Keep the three roots separate and outside Git.
- Do not scan, open, copy or create token-bearing `.cdsapirc` files. An explicitly authorized official client may internally reuse the user's existing file; this does not permit agent inspection or migration into workspace, non-secret configuration or Git. Do not put tokens in JSON, command lines or logs. The runner does not load credentials on the user's behalf.
- ERA5 acquisition does not convert GEOS-Chem meteorological forcing; check version-specific input contracts separately.
- Matching [PM2.5 stations](../../03_atmospheric_transport/pm25-stations/SKILL.md) is a separately scoped preparation task. Check station time zone, averaging, spatial matching and representativeness. Meteorological grids are not pollution observations. Primary stage is 01, referenced by 03/04 without duplicating the workflow.
