# 工具注册与查询：第一版实现范围

本轮按已有注册规范实现仓库工具目录，接入现有 CLI、Python/R 脚本，同时区分需适配模板和操作参考。

1. `catalog/tools/*.yaml` 是工具元数据唯一来源，`catalog/schemas/tool.schema.json` 校验版本、必需字段、类型与允许的参数绑定。重复 ID、重复 YAML 键、未知字段、越界路径或外部 schema 引用均拒绝。
2. `ToolRegistryService` 提供分类/skill/关键词/状态筛选、详情和本机前置条件检查。`list-tools` 默认分类表格，机器声明固定 `--format json`；`describe-tool` 提供完整声明，`check-tool` 提供检查结果。
3. 检查仅查询当前解释器的依赖发行包元数据、PATH 中可执行程序及明确配置的非秘密目录/文件元数据。禁止导入 skill 代码、执行命令、联网或读取个人配置、cookie、token、浏览器 profile 内容。
4. 配置检查规范化路径，要求数据、配置、认证根在 Git 仓库外且互不重叠；模型/输入/输出不得进入个人配置或认证根。输出变量须位于工作区的 `output/` 下。结果只返回变量名与逻辑路径。
5. 状态包含缺少入口、缺少依赖、缺少/无效配置、认证待验证、人工条件待验证及就绪。`ready` 仅指本轮静态前置条件通过；R 包、真实输入、登录及科学验收不因工具登记而自动通过。
6. 第一版登记可直接调用的真实入口及参数，不提供通用执行器、MCP 或网站面板。查询没有写入或下载副作用；执行仍按分类说明显式调用原 CLI/脚本。后续执行器需单独实现参数绑定、授权和输出验收。

验收覆盖真实目录筛选、错误注册、依赖和认证状态、路径冲突/链接逃逸、错误脱敏、无执行/无凭据读取以及旧 CLI 兼容性。独立代码审查后修正重要问题。
