# 技能、数据集与工具注册

<!-- README-I18N:START -->

[English](tool-registration.md) | **中文**

<!-- README-I18N:END -->


本规范说明登记边界和已实现行为。具体能力、依赖和清单放在[工具目录](tool-catalog.md)及分类用法中；通用规则不列举模型、框架或技术类别。

## 1. 不同对象分别管理

| 对象 | 权威来源 | 实际效果 |
|---|---|---|
| 技能 | `SKILL.md` 文件头 | 供兼容宿主发现的流程指导 |
| 宿主展示 | 技能中的 `agents/openai.yaml` | 可选展示，不创建函数或登录 |
| 数据集 | 获取技能中的 `datasets.yaml` | 数据目录信息，不下载或验内容 |
| 工具 | `catalog/tools/*.yaml` | 已校验元数据及声明的执行支持 |
| 方法映射 | `methods/index.yaml` | 步骤、技能及真实工具编号的文档关联 |

流程和请求文件不替代实现。方法中的技能路径须指向默认真实入口，工具编号必须存在。参考技能可以没有工具编号。

## 2. 稳定标识

新技能名称使用英文小写字母、数字和连字符；工具编号使用小写字母、数字和下划线。标题供人阅读，不含个人账号、机器名、绝对路径或凭据。

历史文件头名称、数据技能编号、目录和别名可能不同。通过真实元数据和技能说明核对，不按文件夹猜测。保留公开编号，变更时明确迁移。别名不证明对应数据的范围或完整性。

## 3. 新增技能

遵守双语[编写规范](skill-authoring_ZH.md)：

1. 明确独立任务，选择现有分类、阶段或共享位置。
2. 同时编写中英文入口，包含稳定名称、用途、输入输出、前置条件、步骤、失败和验证。
3. 通用方法正文放方法库，跨阶段原则放共享方法；接口步骤放参考资料，已审查实现放脚本，需适配代码放模板，公开或合成示例放示例目录。
4. 确有需要时增加可选宿主信息。
5. 有真实目录需求时才声明数据集，不为展示虚构数据或工具。
6. 更新两种语言的分类导航及方法映射，不重复复制流程。
7. 按声明的证据层次验证发现、已有调用及失败处理，授权共享前审查隐私。

默认入口参与发现，译本不是第二个注册能力。独立分发时携带资源或固定版本公开链接，仓库相对引用不会自动随复制的目录提供。

## 4. 数据集声明

责任技能声明 `skill_id`、`layer` 和仓库相对 `skill_path`。记录包含服务要求的编号、名称、领域和描述，并写清获取方式、来源、覆盖及逻辑缓存根。

使用 `${AIRMOSAIC_LOCAL_WORKSPACE}`，不写私人映射、真实缓存清单或凭据。检查列表、详情、筛选、唯一性和引用。当前加载器不自动落实全部结构和重复编号约束，不能声称已经自动保证。

`catalog/datasets/` 还作为详情查询的后备来源，仅增加后备记录不保证出现在列表。相同编号明确权威声明，避免漂移。

## 5. 工具元数据

每项工具一个声明文件，使用[结构定义](../catalog/schemas/tool.schema.json)。[列表查询声明](../catalog/tools/airmosaic_list_tools.yaml)是真实示例。

| 字段 | 要求 |
|---|---|
| `schema_version`、`tool_id` | 支持的版本，目前为 1；稳定唯一编号 |
| `title`、`description`、`category`、`skill_id`、`owner_role` | 公开用途、分类、真实技能与维护角色 |
| `implementation_status`、`registration_status` | 如实说明实现、模板或参考及登记状态 |
| `entrypoint` | 真实相对路径和受支持类型，按需声明命令模块及子命令 |
| `input_schema`、`argument_bindings` | 字段与旗标或位置绑定一致，不接受任意命令代码 |
| `default_arguments` | 经审查的默认值，结构化查询使用声明格式 |
| `output_schema` | 预期响应或产物，不声称原脚本都是服务 |
| `requirements` | 依赖、程序、非秘密配置、固定资源及人工检查 |
| `authentication`、`effects` | 逻辑认证方式及读写联网副作用，不含秘密或真实配置路径 |
| `documentation` | 存在的分类用法文档 |
| `execution` | 启用状态、适配器与路径角色和审查策略一致 |

加载器拒绝未知字段、重复键或编号、缺少绑定、不支持版本、不安全路径及外部结构引用。只有声明不能执行任意代码，还需审查允许清单、资源路径输入结果检查，以及有效合成测试。模板和参考保持禁用。

任务文件只含参数，不含工具外壳。执行入口另传工具编号，可先补齐输出字段再校验。调用方结构快照是说明，不是登记权威，应与示例同步。人工计划明确不可执行，不虚构动作。

新增工具先限定真实动作、核对解析器，声明副作用和认证；再校验目录、查看详情和状态、测试正常及拒绝输入、更新用法并审查隐私。资源检查限定在明确配置根下的固定相对位置。就绪状态按成员环境检查，不提交个人登录或依赖状态。

## 6. 宿主发现与额外接口

技能目录是源码来源。按路径读取，或安装、链接到宿主支持的位置；核对冲突，不覆盖个人技能。项目没有自动安装器，不能假定任意源码目录会自动发现。

在真实宿主核对名称和调用。展示信息可设置名称、简述和默认提示，不创建函数、不登录、不启动服务。分发携带资源并跟踪版本。

额外服务适配器尚未实现。未来接口须先实现真实列表与调用、输入结果检查、错误和授权，再展示可调用工具。元数据和行为提示不强制落实权限；参考文件和未适配模板不得作为执行函数。

## 7. 展示与就绪状态

依据分类和真实声明展示用途、入口类型、实现、当前环境及下一步，明确模板、参考和规划能力。

实现状态、证据与当前就绪分别管理。状态值以加载器真实响应为准，不虚构枚举，不将登记等同就绪。源码审查、合成小样、集成和科学验证分别记录日期与证据。

详情包括调用、字段、单位、依赖、认证、读写联网范围、失败和验证。公开展示使用逻辑路径，完整路径只留在授权本地界面。现有命令、结构化结果与文档导航不表示工具面板、安装器或额外服务已经实现。
