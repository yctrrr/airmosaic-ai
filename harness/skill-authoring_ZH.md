# 新增与维护技能规范

<!-- README-I18N:START -->

[English](skill-authoring.md) | **中文**

<!-- README-I18N:END -->

本页是新增和修订技能的编写清单。执行注册与宿主发现另见[注册规范](tool-registration_ZH.md)。编写说明不授权数据访问、下载、模型运行、安装或发布。

## 1. 确定范围与位置

按任务职责和适用阶段确定归属目录。跨阶段能力放入共享目录，已有分类保持稳定。每个技能围绕一个清晰任务，避免在不同目录重复维护同一流程；编写前先阅读相关技能和方法。

通用编写规范不列举具体模型、框架或技术类别，也不将其作为目录规则。具体名称、依赖与调用示例放在对应技能及分类导航中。

第二步始终仅列概念方法，不含具体数据、参数值、实现代码、项目脚本名、源码指纹或执行命令。新增导航不改变此边界。

## 2. 中英文分开，标识保持一致

英文入口使用 `SKILL.md`，中文使用 `SKILL_ZH.md`。其他文档保留默认文件名作为英文版，中文增加 `_ZH.md`。两版顶部各有一组相互切换链接；内容、能力状态、示例、日期和边界同步维护，不在段落或表格中逐句混写。

工具编号、命令、旗标、配置键、数据字段、路径、来源标识和专名保持原样。用于匹配的中文原始表头属于来源字面值，不能当正文翻译。解释性注释可翻译，但不能改变执行行为。

宿主正常发现只使用默认 `SKILL.md`；中文版不是第二个技能或工具。存在同语言参考时优先链接，否则保留真实参考，不虚构译本。本轮入口整理不包含历史长篇参考资料。

## 3. 技能最小内容

文件头必须包含稳定的 `name` 与针对任务的 `description`。新名称使用英文小写字母、数字和连字符，不含私人信息。既有公开编号保留，需变更时明确迁移，不静默重命名。

正文组织应讲清以下内容：

| 内容 | 必须说明 |
|---|---|
| 用途与触发 | 解决什么任务，何时改用相关流程 |
| 当前能力 | 已实现适配器、人工流程、模板或参考，以及已有真实工具编号 |
| 输入输出 | 格式、逻辑路径、单位、时空范围、字段及映射 |
| 前置条件 | 依赖、版本、登录权限与人工准备 |
| 操作流程 | 选择、准备、调用、检查和交接步骤 |
| 失败与停止条件 | 依赖或权限错误、任务状态不明、部分输出及安全重试检查 |
| 代理边界 | 授权范围、读写联网副作用、凭据分离及原件保护 |
| 验证与证据 | 已测内容、日期版本、合成与真实检查区别，以及未验证项 |

不把整份手册复制进入口。条件性操作细节放参考资料，通用科学解释放方法库。

## 4. 资源归位

| 资源 | 用途 |
|---|---|
| `SKILL.md` / `SKILL_ZH.md` | 任务选择、流程和行为边界 |
| `methods/` | 科学方法、来源、误差、规范化与质量规则的唯一正文 |
| 技能 `references/` | 工具接口、操作步骤与验证示例 |
| `scripts/` | 已审查的确定性实现 |
| `templates/` | 需要适配的代码，未实现前不作为执行器入口 |
| `examples/` | 合成或通用任务参数，不含私人路径或秘密 |
| `agents/openai.yaml` | 可选宿主展示信息，不是执行注册 |

数据来源需说明原生产者与实际提供者、产品身份、版本、覆盖、单位、时间语义、缺失、质量规则及有日期的原始依据。唯一正文放方法库，由技能链接。真实获取示例记录带时区的实际操作时间，不给未执行步骤填写时间。

## 5. 区分技能、数据集和工具

| 对象 | 登记来源 | 登记证明什么 |
|---|---|---|
| 技能 | 默认文件头及宿主支持的发现位置 | 可发现的指导，仍需实机核对 |
| 宿主展示 | `agents/openai.yaml` | 展示字段，不完成登录或创建函数 |
| 数据集 | 确有声明需要时的 `datasets.yaml` | 数据目录信息，不证明获取成功 |
| 工具 | `catalog/tools/*.yaml` | 工具元数据及声明的执行支持 |
| 方法映射 | `methods/index.yaml` | 步骤、技能和工具的文档关联，不授予执行权限 |

参考技能可以没有数据集或工具编号，不为展示虚构它们。可执行工具还需要审查执行器策略与适配器，并提供有效合成测试；仅加声明不能执行任意代码。已实现适配器使用真实编号及统一执行入口，保留注册规范中的历史标识差异。

## 6. 路径、凭据与数据边界

仓库外三个已存在根目录相互独立：`AIRMOSAIC_ASSETS_DIR` 存数据结果，`AIRMOSAIC_CONFIG_DIR` 存非秘密设置，`AIRMOSAIC_AUTH_DIR` 存浏览器状态。凭据留在秘密管理器，或由明确授权的官方客户端使用本人已有凭据机制，不读取、复制或暴露秘密。模型发行包留在仓库外，新结果使用独立任务目录。

说明维护只用接口和合成输入，不读取既有原始数据。共享文档、示例和日志不得包含用户名、密码、密钥、会话、私人主机、机器专用绝对路径、签名链接或个人任务引用。明确参考流程没有落实的运行保护；行为说明不是操作系统隔离。

## 7. 新增步骤

1. 确定独立任务、研究步骤、状态及允许的副作用。
2. 同时编写中英文版本，链接方法及操作参考。
3. 仅增加必要示例、模板或脚本，保留原件和无关修改。
4. 确有需要时按独立规范增加数据集、工具或宿主信息。
5. 更新两种语言的分类导航，必要时更新方法映射。
6. 完成下列检查和隐私审查；真实获取或模型运行另需明确任务范围。
7. 当前任务明确授权提交与推送后，才提交经过检查的具体变更。

## 8. 交付前检查

- 检查文件头和稳定标识，中文版描述同一能力。
- 检查语言切换、相对链接、翻译后的锚点及同语言导航。
- 对照两版的可执行命令、编号、参数、路径、默认值和验证状态。
- 核对引用文件及真实声明，模板和参考保持不可执行。
- 元数据改变时使用只读工具列表、详情、状态及数据目录查询，不将它们当作真实执行证据。
- 实现变化先做有效合成成功及失败测试，再做已授权的集成检查；纯翻译不运行数据或模型。
- 扫描共享变更的私人信息，不回显秘密；区分真实秘密和合成测试值。
- 独立分发时包含必要资源或固定版本公开链接；仓库相对引用不会自动随复制的技能目录提供。

面向人类的完整路径放在 `methods/pathways/`，未来可执行定义放在 `workflows/`。说明与定义都不是可发现技能，也不代表引擎已实现。参见[布局说明](project-layout_ZH.md)。
