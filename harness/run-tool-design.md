# run-tool：受控执行第一版

当前目录约定见[资产规范](assets_ZH.md)。下文历史设计或验证记录中的旧路径属于当时版本；不会自动迁移真实数据。

最初范围：核心 CLI 和六个 Python 脚本。当前扩展到两个既有 GCAM R 脚本；模板、参考和嵌套 run-tool 仍不支持。

1. 使用现有 manifest 输入 schema 和参数绑定。新增明确的 execution 策略，限定适配器、输入/输出参数角色和自动输出位置；未知参数、错误类型和不安全路径在启动前拒绝。
2. 数据、个人配置、认证根必须分开并位于 Git 外。只读取明确指定的非秘密 JSON 参数文件；不自动加载个人配置或认证材料。输入文件限于工作区的数据缓存/既有任务输出，模型读取使用经检查的 GCAM_RELEASE_DIR。
3. 新输出全部进入 `output/<UUID>/<tool_id>/`，记录进入 `runs/<UUID>/record.json`，临时 HOME/TEMP 进入 `temp/<UUID>/`。不覆盖旧任务、不自动迁移缓存。WorldPop 下载也先落到任务目录；数据发布到共享缓存另行处理。
4. dry-run 校验参数与路径并返回脱敏计划，既不运行子进程也不创建记录/目录；依赖缺失和网络/认证许可缺失作为计划的阻塞原因展示。
5. 实际运行使用参数数组、当前 Python 的隔离模式、任务工作目录和允许字段构建的环境，不继承 token、代理凭据、Python 注入变量或真实个人 HOME。联网需 --allow-network，GBD 还需 --confirm-browser-session；该确认是成员对会话授权的声明，不是自动登录核验。
6. 记录只保留公开工具 ID、源码/manifest 摘要、参数名与类型、权限标志、UTC 时间、退出状态及逻辑位置。丢弃脚本原始 stdout/stderr。核心 CLI 输出只返回有界、脱敏摘要，不保存自由文本、实际路径或文件名。
7. 支持超时与本任务进程树取消；错误只输出受控类别。科学数据文件属于个人任务产物，不能当作已脱敏的运行记录自动分享。
8. 这是针对已审查入口的参数/环境/路径控制，不是操作系统沙箱；不能对恶意脚本、替换中的文件系统或模型二进制承诺完整隔离。需要强制隔离时使用独立运行账户/OS 权限。

验收：参数失败不启动、dry-run 无副作用、路径穿越/链接/认证目录拒绝、环境秘密不继承、日志不包含原始参数/输出、真实合成脚本成功/失败/超时、原 CLI 兼容，并通过独立只读审查。

## GCAM R 接入扩展（2026-10-23）

复用现有 schema、ExecutionPaths、子进程所有权/超时和脱敏记录；增加 gcam_inspect / gcam_plot 两个明确的 R 适配器，不允许任意 R 脚本。R 用 --vanilla 和固定启动表达式先验证包，再 source 既有入口，参数仍由原解析器读取。dry-run 不启动 R，包状态明确留待执行核验。

结构检查固定读取模型根下数据库与映射，不开放 release_dir 参数覆盖；max_memory 使用 schema 校验和固定默认。绘图必填工作区 input_csv，out_dir 仅通过审查过的 env:UNIT_PRICE_OUT_DIR 绑定传递。两者输出均自动限定在新任务目录。检查预期文件以识别原结构脚本捕获查询错误后仍退出 0 的情况。

保留全部 XQuery、筛选、年份和加权计算；仅修正结构脚本的 Java 启动参数：对 system2 参数逐个引用，直接传入 .xq 文件，避免把 RUN 字符串当作 XQuery。[BaseX 命令行文档](https://docs.basex.org/main/Command-Line_Options)说明输入文件会作为 XQuery 执行。用真实 R/Java 与合成 CSV/BaseX 数据库验证，缺依赖时明确跳过，不将合成检查称为科学验收。
