## 2. 各层职责

| 层次 | 职责 |
|---|---|
| 技能 | 任务适用性、步骤、输入输出与限制 |
| 工具 | 已实现入口完成一个明确动作，模板必须标明状态 |
| 数据目录 | 来源、责任技能和缓存元数据，不执行获取 |
| 工作流 | 交接与假设，设计不等于编排实现 |
| 执行约束 | 预检、受控调用、状态和记录，仅覆盖支持的适配器 |
| 验证 | 接口、产物与独立科学检查 |

任务授权 → 发现能力 → 检查输入、依赖及写入范围 → 执行已实现入口 → 验证产物与方法 → 保留本地证据 → 脱敏交付。

## 3. 成员分工

使用者明确范围与结果用途；领域贡献者说明方法、单位、假设和验收标准；平台维护者保持接口、元数据与环境兼容；审核者复核最小案例、科学口径和真实变更。

角色可以兼任，科学计算改变应有独立领域复核。角色、仓库权限与任务授权分别管理。每人使用自己的账号、仓库副本、环境和任务目录；共享输入只读，不并发覆盖缓存或输出。

## 4. 一次任务的执行

1. 明确对象、年份、地区、结果、操作及资源上限。
2. 阅读技能，核对真实入口。
3. 检查环境、权限、输入存在性和版本。
4. 核对字段、单位、时空、来源与覆盖。
5. 明确授权读写、网络副作用及覆盖行为。
6. 执行已核对命令，记录完成、等待或失败。
7. 分别检查产物与科学口径，不以进程成功代替验收。
8. 交付结果、证据和限制，不附私人身份、凭据或机器路径。

持续完成已授权可逆工作，不重复确认。缺少必要信息或授权时再补充；说明不授权安装、下载或耗时任务。

任务描述应包括仓库入口、有限问题、允许输入和操作、所需证据、缺失处理及脱敏要求。不静默补零、换年份、改分辨率或扩大范围。

## 5. 路径与数据

仓库仅存可复用代码、文档、结构定义和已声明演示资产。私人 `AIRMOSAIC_ASSETS_DIR` 保存共享的 `data/<stage>/<dataset-name>/<version>/`、新的 `results/<project_id>/<run_id>/<stage>/<tool_id>/`，记录与临时文件位于同次运行的 `records/<tool_id>/`、`temp/<tool_id>/`；个人配置与认证分别保存在仓库外独立根目录。

新任务显式覆盖旧输出默认值，不迁移旧文件。外部发行包单独配置为只读输入，修改配置使用任务副本。共享说明使用逻辑根和编号，变量字符串仅在调用方实现解析时展开。

## 6. 工具使用

只读发现和状态检查不执行动作，也不证明科学有效。查看真实声明，支持的适配器使用[统一执行](usage/run-tool.md)。预检核对 `can_execute`、`blockers`，实际运行核对状态与产物。

路径检查、最小环境和脱敏记录只覆盖已审查适配器，直接脚本不继承。执行器不是操作系统沙箱。认证、依赖加载、真实集成和科学验收分别核对。本地标准输入输出 MCP 已可使用，安装、资源阅读及逐工具启动授权见[连接指南](usage/mcp_ZH.md)。工作流编排和远程服务接口仍是设计。

## 7. 验证与交接

本地记录来源与配置版本、范围、参数、输入输出及验证状态。完整诊断仅留在授权位置，且不含秘密；共享逻辑编号、相对路径、数量、单位和脱敏错误。区分源码审查、合成检查、真实集成及科学验证。文件存在或进程成功不足以验收。

交接说明唯一键、单位、时空支持、缺失、映射、不确定性与证据。上游成功不自动授权串联或发布缓存。

## 8. 贡献与发布

限定变更范围，检查已有工作，按需使用独立分支或副本；维护双语说明，遵守[编写](skill-authoring_ZH.md)和[注册](tool-registration_ZH.md)规范。相关检查及隐私审查通过后执行已授权的提交、推送或发布。

区分已授权前置改动与无关工作。不强制推送、改写历史，也不因角色或计划而启动后续工程或改变仓库权限。后续分发和接口只有实现并按任务验证后才能称为可用。

## 数据与项目结果

数据和项目结果按[资产规范](assets_ZH.md)管理。Git 外共享 `assets/data/<stage>/<dataset-name>/<version>/`，数据目录使用实际名称；项目按配置引用固定版本，跨阶段不复制。新结果保存到 `assets/results/<project_id>/<run_id>/<stage>/<tool_id>/`，运行记录和临时文件留在该批次内。新调用同时提供项目和阶段。计算与检查 → 人工复核 → 将选定数据登记到新版本；不覆盖原始数据或既有版本。个人配置、认证及凭据继续独立管理。旧文件不迁移，自动审批和入库服务尚未实现。
